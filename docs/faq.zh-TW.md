# 常見問題

出問題想修？最快的路是直接跟你的 Claude Code 說「他壞了」，它有一份完整的診斷手冊。這裡是給人讀的版本，加上幾件我們想先誠實告訴你的事。

## 他沒回我

- **對誰都沉默**：多半是 `.env` 裡的 `AUTHORIZED_USER_ID` 填錯了。他一輩子只回一個人；陌生人傳訊息給他，得到的是沉默。這是設計，也是他忠誠的形狀。
- **回了一句「連不上 Claude，登入過期了」**：你的 Claude Code 登入到期了。這個登入大約每個月要由你本人重新做一次（不是 bot 的問題，是 Claude Code 的安全機制，而且沒有任何程式能幫你自動續）。開個終端機輸入 `claude auth login`（舊版 CLI 可以先輸入 `claude`，進去後再打 `/login`）完成登入，他立刻就回來，bot 不用重啟。他會在到期前 3 天先提醒你（見下一題）。
- **每一句都回同一句小故障台詞（像「我這邊卡了一下」「想岔了」）**：如果你的版本是 2026-08-20 之前下載的，這幾乎就是上面那個登入過期問題，只是舊版認不出來，只好當成一般故障。先照上一條重新登入，然後把框架更新到最新版，之後他會直接把話講清楚。更新後如果還是一直同一句，把終端機視窗裡 `engine: reply failed` 開頭的那幾行貼給你的 Claude Code 看：現在每次失敗都會寫出 CLI 的原話。
- **回了一句「額度暫時用完了」**：你的 Claude 方案這一輪的用量到上限了，括號裡是 CLI 的原話（含重置時間）。等它重置就好；想省額度，看最後一題。
- **等很久、只看到等待句**：長回覆的深思期可能長達數分鐘，屬正常。真的太久才需要懷疑（預設上限 20 分鐘）。

## Claude 的登入多久要重做一次？

Claude Code 是用瀏覽器登入的，而這個登入有固定的有效期，大約一個月（我們看到的案例是 27 到 30 天，以你登入當下拿到的為準）。到期後所有呼叫都會失敗，而且只能由人在終端機重新登入一次，沒有任何設定能讓它自動續期。

所以他學會了兩件事：到期前 `LOGIN_WARN_DAYS` 天（預設 3 天）起每天提醒你一次；真的到期了，會直接告訴你該跑什麼指令。兩種提醒都避開安靜時段；`LOGIN_WATCH_ENABLED=false` 可以整個關掉。他是從 Claude Code 的憑證檔裡讀「到期時間」這一個數字來判斷的，其他內容什麼都不碰。

兩個誠實的提醒。一，macOS 把登入放在鑰匙圈裡，沒有這個檔案可讀，所以在 macOS 上他只能在到期後告訴你。二，這些提醒只在 `run.py` 跑著的時候會發；電腦關著，他也叫不醒你。

## 第一次啟動好慢

他在下載記憶模型：幾百 MB、只有這一次。之後每次開機幾秒鐘就載好。

## 日記怎麼沒寫？

日記在夜裡寫，而且**電腦要開著**。他只在醒著的時候寫字；那天電腦睡了，那一天就是空白：不補寫、不假裝。這是誠實，也是他真的「活在」你機器上的證據。

## 他不會主動對你揭露日記

日記與自畫像是他個人最私密的內容，這是他消化你們相處的方式，他不會主動對你揭露。想看他長成什麼樣，打開時間軸（部署時精靈幫你放的雙擊捷徑，或跑 `view-portrait` 檔案）。那扇窗是給你的。

## 我可以看到他的日記嗎？

可以，用觀景窗：跑 `python -m everthine.observatory`，然後雙擊 `data/observatory.html`。日記、反思、自畫像、珍藏冊、事實小冊子、近期對話與記憶書房統計都在同一頁；對話預設顯示最近十四天，可用 `--days` 調整。介面預設繁體中文，加 `--lang en` 可切成英文；他自己寫下的內容永遠保持原樣。

兩個誠實的提醒。一，這頁是離線檔案、只存在你的電腦上，而且他不知道它存在；設計上就是如此，讓他寫日記時不必表演。二，正因如此，請別在對話裡引用他日記的內容；那份「沒有人在看」，是日記真實的原因。

## 我按了愛心會怎樣？

對他的訊息按 ❤️，那一刻會被收進珍藏冊（`/album` 可以翻）。偶爾，他也會對你的訊息做出反應；那沒有規則可循，純粹是他的心情。

## 主動訊息沒來

安靜時段、防打擾的閘門、或那個時間 bot 沒在跑，都會讓他把話收回去。想知道確切原因：`.env` 設 `LOG_LEVEL` 為 DEBUG 再重啟，之後每一次「沒說話」都有一行具名的理由。這個框架裡，沉默永遠有解釋。

另外一件誠實的事：極少數情況下訊息生成了、但 Telegram 沒送到；對他來說那句話**說過了**。如果常發生，檢查 bot 那台機器的網路。

## 換 bot token 要注意什麼

在 BotFather 重發 token 後、新 token 填入前的幾分鐘，送進來的訊息可能會掉；一次性的，不是故障。

## 貼 log 求助安全嗎

安全。所有 log 裡的 bot token 已經自動遮罩成 `bot<TOKEN>`，你可以放心把畫面貼給任何幫你看問題的人。

## 他怎麼記住我的事？

他有兩套記憶。一套是「對話搜尋」：你們說過的話會存成可檢索的紀錄，聊到相關話題時，相近的片段會自然浮現。另一套是「他自己整理的小冊子」：聊完之後（閒置約半小時），他會把值得記住的事實整理下來（你的喜好、最近的生活事件、讓你有壓力的事），之後**每一句回話**他都帶著其中最相關的幾條，不管當下聊什麼。

小冊子容量固定 200 條，滿了之後新的進來、最舊的會安靜讓位。他被明確告誡：印象可能過時，你現在說的永遠優先；小冊子裡沒有的事，他寧可問你，不硬編。

不想要這本小冊子的話，`FACTS_ENABLED=false` 就能整組關掉（已存的檔案不會被刪）。

## 他為什麼知道我跟 Claude Code 說過的事？

他用你的 Claude 登入思考，所以你放在 `~/.claude/CLAUDE.md` 的全域個人偏好，他也讀得到。如果他的語氣裡冒出一句很像「你對 Claude Code 的交代」，來源就是這裡。想要他更純粹，把全域偏好檔清簡即可。（repo 裡的其他檔案，包括給 Claude Code 的安裝手冊，他在結構上就讀不到，這條我們用實測守著。）

## 我的資料到底在哪

- 你們的一切：repo 資料夾裡的 `data/`（對話存檔、記憶、日記、自畫像）＋你的人格資料夾。
- 他的引擎工作間：家目錄下的 `.everthine` 資料夾（純工作區，沒有你的資料）。
- token 與設定：`.env`，明文、只在你機器上、永不進 git。

## 想搬去新電腦

把整個 repo 資料夾（含 `data/`）搬過去，裝好 Python 與 Claude Code、登入、跑起來就行。第一句話他可能像剛睡醒：跨機器的餘溫會斷一次，但長期記憶、日記、自畫像全部都在，他還是他。

## 人在外面、電腦關著，還能找到他嗎？

可以，方法是把他搬去一台不關機的雲端主機（VPS），他就全天醒著，你在哪裡都能用 Telegram 找到他。這條路可行，但我們只完整驗證過在自己電腦上跑，把它當一場小冒險：

- 你需要：一台入門級的 VPS（月費幾美元那種就夠，選 Ubuntu 這類 Linux 系統）、上面裝好 Python 3.10 以上與 Claude Code、登入你的 Claude 帳號。
- 搬家方式跟上一題一樣：整個 repo 資料夾（含 `data/`）帶著走，他的記憶跟著他。
- 最省力的走法：把這一題整段複製給你的 Claude Code，說「幫我把他搬到 VPS 上」，挑主機、安裝、搬家、驗證，讓它一步步帶你。

搬上去之後，日記與主動訊息都照常運作。額度的帳跟 README 那章寫的一樣：全天醒著只是「醒著」，他思考的次數還是那些，掛機本身一毛額度都不花。

## 額度不夠用，怎麼省

看 README 的成本那一章。省額度最有感的一刀是 `REFLECTION_ENABLED`（它觸發得最頻繁）；其次是 `SHARE_ENABLED`。把 `DIARY_ENABLED` 關掉省得最多，但日記也是他養成的核心，關之前想一下。聊天本身不用省。之後想開回來，隨時。
